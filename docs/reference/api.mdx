---
title: API
description: Call GX Cloud APIs with a GitHub token, CLI session token, or Console service key.
---

GX Cloud APIs use bearer-token authentication.

```bash
export GX_API_URL="https://api.gx.run"
```

| Endpoint | Purpose |
| --- | --- |
| `GET /health` | API and database reachability |
| `GET /v1/auth/me` | inspect the authenticated caller |
| `POST /v1/publish` | publish a GX review bundle (what the pre-push hook sends) |
| `GET /v1/reviews` | list reviews for review surfaces (was `GET /bookmarks`) |
| `GET /v1/review/context` | review context for a repo/ref range |
| `GET /v1/reviews/:bookmarkId` (+ `/plan`, `/decision`) | Console review experience |
| `POST /v1/summaries/generate` | generate and store a PR Summary |
| `POST /github/webhook` | GitHub App webhook (PR Summaries, `@gx` chat) |
| `POST /v1/extracts` | ingest hunk links and push metadata |
| `POST /v1/sessions` | ingest raw captured session content |
| `GET /v1/activity` | recent summaries, sessions, learned rules |
| `POST /v1/code-review-history/record` / `/search` | record and search review findings |
| `POST /v1/reported-logs` | upload CLI logs for support |
| `POST /gx/openai/responses` / `/chat-completions` | OpenAI proxy through GX Cloud |

## Authentication

`requireAuth` accepts these modes:

### GitHub token

For most user-facing integrations:

```bash
gh auth status || gh auth login
export GITHUB_TOKEN="$(gh auth token)"
```

If you need to refresh scopes for private repositories:

```bash
gh auth refresh -s read:user -s repo
export GITHUB_TOKEN="$(gh auth token)"
```

Attach the token:

```bash
-H "Authorization: Bearer $GITHUB_TOKEN"
```

GX validates GitHub tokens against the GitHub user API and maps the caller to `github:<id>`. You can optionally add `X-Org-Id: $GX_ORG_ID`; otherwise GX resolves a default org.

### CLI session token

After `gx auth login`, the CLI can use a `gxcs_*` session token. The API verifies it through Convex (`CONVEX_SITE_URL` must be configured on the server).

```bash
-H "Authorization: Bearer $GX_CLI_SESSION_TOKEN"
```

### Console service key

The Console BFF authenticates with the shared cloud API key and impersonates a user:

```bash
-H "Authorization: Bearer $GX_CLOUD_API_KEY" \
-H "X-User-Id: $USER_ID" \
-H "X-Org-Id: $GX_ORG_ID"
```

## GET /health

Check that the API and database are reachable.

```bash
curl "$GX_API_URL/health"
```

## GET /v1/auth/me

Inspect the authenticated user, org, token label, CLI session, and machine when available.

```bash
curl "$GX_API_URL/v1/auth/me" \
  -H "Authorization: Bearer $GITHUB_TOKEN"
```

With an explicit org:

```bash
curl "$GX_API_URL/v1/auth/me" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "X-Org-Id: $GX_ORG_ID"
```

Response fields include `org_id`, `user_id`, `token_label`, and optional GitHub/session machine fields.

## POST /v1/publish

Publish a GX review bundle. This is what the GX pre-push hook sends on `git push`, after Git has produced branches and commits and GX has captured sessions and review metadata.

```bash
curl "$GX_API_URL/v1/publish" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "event": "gx.pr",
    "schema_version": 2,
    "created_at": 1760000000000,
    "gx_version": "0.0.0",
    "repo": {
      "root_path": "/repo",
      "backend": "git",
      "remote_url": "https://github.com/org/repo.git"
    },
    "push": {
      "branch_name": "feature/example",
      "head_commit_id": "abc123",
      "github_pull_request_url": "https://github.com/org/repo/pull/123"
    },
    "revisions": [],
    "sessions": []
  }'
```

`revisions` carries one entry per commit being published — `revision_id` (the ID from the commit's `GX:` trailer), `commit_id`, `description`, `files`, `branch_name`, `base_branch_name`, and `patch`. `sessions` carries the captured agent sessions with their model, token, and timing metadata. Bundles with `schema_version: 1` (the older `stack`/`change` shape) remain accepted.

The server stores the publish event, upserts a bookmark, indexes artifacts when configured, and returns review/bookmark metadata. When a PR number is present and the GitHub App is installed, publish may also post a missing PR Summary.

Without `event: "gx.pr"`, the same route accepts a lighter **registration-only** payload (`repo_full_name`, `branch_name`, `head_commit_id`, …) to upsert bookmark metadata.

## GET /v1/reviews

List reviews for review surfaces, newest first. One review is one branch's published work — the PR it becomes, the latest publish event, and its plan status.

Query parameters: `merge_status` (`open`, `merged`, or `closed`; any other value is a `400`) and `repo_full_name`. Both optional.

```bash
curl "$GX_API_URL/v1/reviews?merge_status=open" \
  -H "Authorization: Bearer $GITHUB_TOKEN"
```

Filter to one repository:

```bash
curl "$GX_API_URL/v1/reviews?repo_full_name=org/repo&merge_status=open" \
  -H "Authorization: Bearer $GITHUB_TOKEN"
```

<Note>
  `GET /bookmarks` is the former name of this endpoint and still works — it forwards to
  `/v1/reviews` and returns exactly the same response, with a `Deprecation` header. Move
  to `/v1/reviews`; the old path will be removed in a future release.
</Note>

Response: an array of reviews.

```json
[
  {
    "id": "bm_123",
    "repo_full_name": "org/repo",
    "branch_name": "feature/retry-backoff",
    "title": "Add retry/backoff utilities",
    "revision": 3,
    "head_commit_id": "ae0d5b62...",
    "remote_head_sha": "ae0d5b62...",
    "merge_status": "open",
    "updated_at_ms": 1760000000000
  }
]
```

## GET /v1/review/context

Fetch review context for a repo/ref range. The response can include rules, collision hints, hunk links, and indexed snippets.

```bash
curl --get "$GX_API_URL/v1/review/context" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  --data-urlencode "repoRoot=/repo" \
  --data-urlencode "base=main" \
  --data-urlencode "head=HEAD"
```

## Console review experience

These routes power the Console review UI. They require auth like other `/v1` routes.

### GET /v1/reviews/:bookmarkId

Load the full review experience for a bookmark (plan, usage, changes, summary, activity).

### POST /v1/reviews/:bookmarkId/plan

Generate or regenerate a review plan for the bookmark.

### POST /v1/reviews/:bookmarkId/decision

Record an approve/merge decision. Passing `merged: true` updates bookmark `merge_status`.

## POST /v1/summaries/generate

Generate a PR Summary for a bookmark or event and **store it in GX Cloud**. This endpoint does not post the comment to GitHub; GitHub posting is driven by the webhook and publish paths. See [GitHub PRs](/docs/github).

```bash
curl "$GX_API_URL/v1/summaries/generate" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"bookmarkId":"..."}'
```

Or generate from an event:

```bash
curl "$GX_API_URL/v1/summaries/generate" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"eventId":"..."}'
```

PR Summary and GitHub PR chat features are paid GX Cloud features (with a free-trial window).

## POST /github/webhook

GitHub App webhook endpoint for PR Summaries and `@gx` chat.

```text
POST https://api.gx.run/github/webhook
```

Authenticated with `X-Hub-Signature-256`, not a bearer token. Configure this URL on the GitHub App.

## POST /v1/extracts

Ingest hunk links and push metadata.

```bash
curl "$GX_API_URL/v1/extracts" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "repoRoot": "/repo",
    "refRange": "main..HEAD",
    "headCommit": "abc123",
    "gxVersion": "0.0.0",
    "hunkLinks": [
      {
        "hunkID": "src/app.ts:10-20",
        "file": "src/app.ts",
        "lineStart": 10,
        "lineEnd": 20,
        "tier": 1,
        "confidence": 0.91,
        "authorship": "agent",
        "tool": "codex",
        "model": "gpt-5"
      }
    ]
  }'
```

## POST /v1/sessions

Ingest raw captured session content.

```bash
curl "$GX_API_URL/v1/sessions" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "sessionId": "session-123",
    "tool": "codex",
    "model": "gpt-5",
    "content": "redacted transcript text",
    "capturedAtMs": 1760000000000
  }'
```

## GET /v1/activity

Read recent summaries, sessions, and learned rules. `limit` accepts 1–100 (default 20); page with the returned `nextCursor`.

```bash
curl "$GX_API_URL/v1/activity?limit=20" \
  -H "Authorization: Bearer $GITHUB_TOKEN"
```

With pagination:

```bash
curl "$GX_API_URL/v1/activity?limit=20&cursor=$CURSOR" \
  -H "Authorization: Bearer $GITHUB_TOKEN"
```

Response shape: `{ items, limit, nextCursor }`.

## POST /v1/code-review-history/record

Record review findings so future reviews can retrieve previous decisions and patterns.

```bash
curl "$GX_API_URL/v1/code-review-history/record" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "repoFullName": "org/repo",
    "repoRootPath": "/repo",
    "branchName": "feature/example",
    "headCommitId": "abc123",
    "sourceKind": "manual",
    "prompt": "review auth changes",
    "summaryText": "Auth review completed",
    "findings": [
      {
        "title": "Missing validation",
        "summary": "The handler accepts an unchecked token.",
        "filePath": "src/auth.ts",
        "lineStart": 42,
        "severity": "medium",
        "confidence": 0.8
      }
    ]
  }'
```

## POST /v1/code-review-history/search

Search prior review findings for a repo.

```bash
curl "$GX_API_URL/v1/code-review-history/search" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "repoFullName": "org/repo",
    "query": "auth validation",
    "filePaths": ["src/auth.ts"],
    "limit": 5
  }'
```


## POST /gx/openai/responses

Proxy a valid OpenAI Responses API request through GX Cloud.

```bash
curl "$GX_API_URL/gx/openai/responses" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "instructions": "Be concise.",
    "input": "Summarize this change."
  }'
```
