The GX MCP server ships with the CLI as a local stdio binary (`gx-mcp`). It shells out to your `gx` binary, so repo state stays on your machine.

## Install GX

```bash
curl -fsSL https://download.gx.run/install.sh | sh
gx auth login
```

That places `gx` and `gx-mcp` in `~/.local/bin`.

If a repo is not initialized, MCP runs `gx init` non-interactively before `gx_review` runs — using Git identity when available, or `GX_MCP_INIT_NAME` / `GX_MCP_INIT_EMAIL`.

## Connect in one command

Use [`add-mcp`](https://www.npmjs.com/package/add-mcp) to register GX with the agents on your machine (Cursor, Claude Code, Codex, OpenCode, VS Code, and more):

```bash
npx add-mcp "$HOME/.local/bin/gx-mcp" \
  --name gx \
  --env "GX_BINARY=$HOME/.local/bin/gx" \
  -g
```

`-g` installs globally so GX is available in every project. Omit it to write project-level config (for example `.cursor/mcp.json`) instead.

Useful flags:

| Flag | Effect |
| --- | --- |
| `-y` | Non-interactive (skip prompts) |
| `-a cursor` | Target a specific agent (repeatable) |
| `--all` | Install to every supported agent |
| `--auto-approve` | Pre-approve tools for Codex / Claude Code |

Most clients only load MCP servers at startup — restart the client or open a new chat after installing.

### Or let `gx init` register

```bash
gx init
```

When supported agent CLIs are on your `PATH`, `gx init` registers GX automatically and reports something like `MCP ok: claude, Cursor`.

## Set up with your agent

Paste this into Claude, Cursor, or any MCP-capable agent:

```text
Help me set up the GX MCP server in this agent.

GX is the quality layer for agent-written code. You keep using plain Git; GX's
hooks record and publish automatically. The CLI installs a local stdio MCP
binary at ~/.local/bin/gx-mcp that exposes one tool, gx_review.

1. If gx isn't installed:
   curl -fsSL https://download.gx.run/install.sh | sh
   then: gx auth login
2. Register the MCP globally with add-mcp:
   npx add-mcp "$HOME/.local/bin/gx-mcp" --name gx --env "GX_BINARY=$HOME/.local/bin/gx" -g -y
3. Tell me if I need to restart or open a new chat, then wait.
4. Once tools are available, confirm gx_review shows up, then walk me through
   the save flow — plain Git: git add → git commit → git push. GX's hooks
   record the revision and publish the review bundle; gx_review is there when
   I want AI review.

Docs: https://gx.run/docs/mcp
```

## Use GX through Executor

[Executor](https://executor.sh) is an MCP gateway: point agents at Executor once, then add GX (and other tools) as integrations behind it. Useful when you already route tools through Executor or want shared policy across agents.

GX is a **local stdio** server, so add it from Executor running on the same machine (CLI or desktop). Stdio integrations spawn a subprocess — enable them only in trusted single-user setups.

### From the Executor UI

1. Install GX (see above) and start Executor locally (`executor install` then `executor web`, or the [desktop app](https://executor.sh)).
2. Open **Add Integration** (or **Add Source**).
3. Choose the **stdio** transport.
4. Set:
   - **Command:** `$HOME/.local/bin/gx-mcp` (expand to an absolute path if the UI requires it)
   - **Name / namespace:** `gx`
5. Optional: add env var `GX_BINARY` = `$HOME/.local/bin/gx`. If omitted, `gx-mcp` looks for `~/.local/bin/gx`, then `gx` on `PATH`.
6. Save, then confirm the tool appears (search for `gx_review`).

Agents that already talk to Executor pick up GX from the shared catalog — no per-client `gx-mcp` registration needed.

### From the Executor SDK

With stdio MCP allowed on the host:

```ts
import { createExecutor } from "@executor-js/sdk";
import { mcpPlugin } from "@executor-js/plugin-mcp";

const executor = await createExecutor({
  plugins: [mcpPlugin({ dangerouslyAllowStdioMCP: true })] as const,
});

const scope = executor.scopes[0]!.id;

await executor.mcp.addIntegration({
  scope,
  transport: "stdio",
  name: "GX",
  slug: "gx",
  command: `${process.env.HOME}/.local/bin/gx-mcp`,
  env: {
    GX_BINARY: `${process.env.HOME}/.local/bin/gx`,
  },
});
```

`env` here supplies values for the connection (Executor stores them and injects them at launch). See [Executor MCP docs](https://executor.sh/docs/mcp-proxy) and [`@executor-js/plugin-mcp`](https://www.npmjs.com/package/@executor-js/plugin-mcp).

### Connect your agent to Executor (not GX directly)

If the agent should only speak to Executor:

```bash
# Local HTTP endpoint (port may differ — use the Connect card in the UI)
npx add-mcp http://127.0.0.1:4788/mcp --transport http --name executor -g

# Or stdio, with the executor CLI on PATH
npx add-mcp "executor mcp" --name executor -g
```

Then add GX inside Executor as above.

## Manual registration

Prefer `add-mcp` when you can. These are the per-client equivalents:

### Claude Code

```bash
claude mcp add gx -- env GX_BINARY=$HOME/.local/bin/gx $HOME/.local/bin/gx-mcp
```

### Cursor

```bash
cursor mcp add gx -- env GX_BINARY=$HOME/.local/bin/gx $HOME/.local/bin/gx-mcp
```

### Codex CLI and Codex app

```bash
codex mcp add gx --env GX_BINARY=$HOME/.local/bin/gx -- $HOME/.local/bin/gx-mcp
```

Or edit `~/.codex/config.toml`:

```toml
[mcp_servers.gx]
command = "/Users/YOU/.local/bin/gx-mcp"

[mcp_servers.gx.env]
GX_BINARY = "/Users/YOU/.local/bin/gx"
```

On Linux, use `/home/YOU/.local/bin/...`.

### Other MCP clients

Same stdio shape:

```bash
env GX_BINARY=$HOME/.local/bin/gx $HOME/.local/bin/gx-mcp
```

Example Cursor / Claude `mcp.json` entry:

```json
{
  "mcpServers": {
    "gx": {
      "command": "/Users/YOU/.local/bin/gx-mcp",
      "env": {
        "GX_BINARY": "/Users/YOU/.local/bin/gx"
      }
    }
  }
}
```

## Tools

| Tool | CLI command | Purpose |
| --- | --- | --- |
| `gx_review` | `gx review [prompt]` | AI review using local and cloud context |

`gx_review` is the only MCP tool. Saving and publishing are plain Git, not MCP calls: `git add` + `git commit` record the revision through GX's hooks, and `git push` captures the session and publishes the review bundle through the pre-push hook. Open the PR with `gh pr create`.

`gx_review` may run up to 5 minutes.

### gx_review

| Parameter | Type | Meaning |
| --- | --- | --- |
| `prompt` | string | optional reviewer prompt, e.g. `"check auth rollback risks"` |
| `scope` | enum | optional focused review scope: `architecture`, `security`, `performance`, `onboarding`, `docs`, `dependencies`, `testing`, `maintainability` |
| `focus` | string | optional; limit review to files under this path prefix |
| `deep` | boolean | optional; full-spectrum review with more local and indexed context |
| `verbose` | boolean | optional; include repo facts, docs, and changed files |
| `repo` | boolean | optional; review the whole repository instead of just the current change (use this to ask about the codebase itself, or when uncommitted work would narrow the review to the diff) |
| `cwd` | string | optional; repository working directory (defaults to the MCP server process cwd) |

## Agent workflow

When a user says "save work", "save using gx", or "save with gx", use plain Git — GX's hooks do the GX work automatically:

1. Stage with `git add` (one logical change per revision)
2. `git commit -m "..."` — a hook records it as a GX revision
3. `git push` for ready stacks (unless they ask to keep work local) — the pre-push hook captures the session and publishes the review bundle
4. Open the PR with `gh pr create` — do not seed a `## Summary`; GX Cloud appends it

Run `gx_review` (or the `gx review` CLI) whenever you want AI review of the current change, typically before pushing.

A typical save sequence:

```bash
git add src/backoff.js
git commit -m "add exponential backoff helper"
git push
```

Provenance is inferred automatically: the pre-push hook matches captured sessions to the hunks they changed, so there is nothing for the agent to attach by hand.

GX PR summaries are posted for PRs whose branch was pushed through GX with `git push` while the pre-push hook is installed. A PR opened before that push will not get a summary until the branch is pushed through GX.

## AGENTS.md instructions

`gx init` offers to append these instructions to your repo's `AGENTS.md`. If you skipped that step, add them manually:

```markdown
Version control: plain Git. Once `gx init` installs the hooks, GX records and
publishes automatically — there is no GX save verb.

Default flow:
- Run `git add` to stage the files for this revision.
- Run `git commit -m "..."` to save. A GX hook records the commit as a reviewable revision.
- Run plain `git push` to publish. The GX pre-push hook captures the session and publishes code changes, sessions, and GX metadata to GX Cloud automatically — do not run `gx push` or `gx capture push` yourself; they bypass the hook.
- Open PRs with `gh pr create` (or the GitHub UI). Do not seed a `## Summary` in the PR body — leave human notes only; GX Cloud appends the rich summary below once the PR exists.

For AI review, run the `gx_review` MCP tool (or the `gx review` CLI) on the current change.
```
