## July 29, 2026

**PR summary verdict labels** — The summary's triage line now states what the reader
must do, not just a color: 🟢 **Quick scan** (LOW), 🟡 **Careful pass** (MEDIUM),
🔴 **Deep review** (HIGH). The label is enforced server-side to always match the
Blast Radius level, so a red summary can never read as permission to skim.

**gx** — The product formerly known as gx is now gx. The CLI is `gx`
(`gxr` for one-shot review, `gx-mcp` for agents). Install from
`download.gx.run`; docs live at `docs.gx.run`.

## July 26, 2026

**Plain Git is the whole workflow** — Capture and publishing are entirely hook-driven:
`git commit` records a revision, `git push` captures the session and publishes. The
porcelain that duplicated Git (`gx push`, `gx sync`, the background daemon, and the
macOS menu-bar app) has been removed. If you have an older install, `gx init` cleans
up the retired pieces.

**PR summaries write to the description** — gx Cloud writes the rich summary
into the pull request description below your own text, behind an gx-owned
marker. Your notes survive every regeneration.

**`gx review` is guaranteed read-only** — Review writes nothing: no repo state, no
`.git/index` mutation, no `~/.gx` on machines that never ran `gx`, and no
uploads when a gate fails. `--fail-on` turns a review into a CI gate with distinct
exit codes for "findings survived" and "nothing was reviewed". See the
[CLI reference](/docs/cli#gx-review).

**Two-model review panel** — `gx review` runs two independent Anthropic reviewers
plus a judge that verifies and dedupes findings. When both reviewers flag the same
issue independently, the report says so — the strongest confidence signal a panel
produces.

## July 2, 2026

**Generated GitHub PR summaries** — After you publish with plain `git push` and open
a PR, gx Cloud posts a generated review summary highlighting blast radius and
high-impact review targets.

**Code review history memory** — `gx review` pulls in indexed context from your past
reviews and GitHub comment history, and attaches review policy context so findings
stay consistent with how your team reviews code.

**Prompted `gx review`** — Trigger `gx review` with a targeted prompt to focus the
review on a specific concern instead of the full default sweep.
