---
title: CLI
description: Use the open-source gx CLI to record revisions, inspect status, review changes, and publish normal Git output.
---

`gx` is the local CLI. It is open source and runs on your machine. It adds a quality and workflow layer around your existing repo instead of replacing GitHub.

GX still produces ordinary Git branches and commits as output. The difference is that GX models the work first as reviewable revisions inside ordered stacks, with captured session context attached.

## Core loop

```bash
git add <files>                        # choose the scope of the revision
gx commit -m "describe this revision"  # record it
gx status                              # inspect stacks (alias: gxs)
git push                               # GX pre-push hook captures sessions and publishes metadata
```

Or publish explicitly with `gx push` instead of `git push`.

## gx init

```bash
gx init
```

Prepares the current repository for GX: configures local identity, installs a Git pre-push hook, installs Claude Code transcript-capture hooks, registers the MCP server with supported agent CLIs, and offers to add GX workflow instructions to `AGENTS.md`.

Run it once per repository.

| Flag | Meaning |
| --- | --- |
| `--name <name>` | user name to store in GX and JJ config (defaults to Git identity) |
| `--email <email>` | user email to store in GX and JJ config |
| `-y`, `--yes` | accept defaults and suppress prompts — use in scripts and agent sandboxes |

```text
$ gx init

Configured     gx identity as Ada Doc <ada@example.com>
Pre-push hook  ok: capture on git push
Claude hooks   ok: Stop/SessionEnd transcript capture
Session        30 days retention
MCP            ok: claude
AGENTS.md      ok: added GX workflow instructions

Next           git add <files> && gx commit -m "..."
```

## gx commit

```bash
git add <files>    # or git add -p to pick hunks
gx commit -m "describe this revision"
```

Records **staged** Git changes as a GX revision. Like `git commit`, the revision lands on the current branch and `HEAD` does not move. The revision is JJ-backed, so it stays editable through GX tools later.

| Flag | Meaning |
| --- | --- |
| `-m`, `--message <msg>` | commit message (required) |
| `-b`, `--branch <name>` | create this branch at `HEAD` and record the revision onto it |
| `--context-file <path>` | JSON file with agent-declared provenance (see below) |
| `--json` | print machine-readable JSON (repo, change, stack, provenance status) |

Exit codes: `0` success, `1` general error, `2` no staged changes.

```text
$ gx commit -m "add exponential backoff helper" -b feature/retry-backoff

Revision recorded
Created branch feature/retry-backoff (from main)
Message       add exponential backoff helper
Revision      qlmmuyyyupkm
Commit        14c101a1
Stack         feature/retry-backoff
Provenance    absent
```

`Revision` is the stable GX change id; `Commit` is the Git commit it exported. `Provenance` reports session linkage: `absent` when no captured session matched, or a linked status when GX matched a captured session or one was attached explicitly (agents attach sessions through [MCP `gx_commit`](/docs/mcp)).

Some `git commit` flags are intentionally rejected, with the replacement in the error message:

- `gx commit -a` — not supported; stage with `git add` first, so the revision scope is explicit.
- `gx commit --amend` — not supported; use `gx edit <rev>` to modify a recorded revision.
- `gx commit -F <file>` — not supported yet; pass the message with `-m`.
- `gx commit <path>` — path arguments are rejected; choose scope with `git add` or `git add -p`.

### Agent-declared provenance

`--context-file` attaches a self-report to the revision. All fields are optional:

```json
{
  "task_summary": "Add retry/backoff utilities requested in TICKET-482",
  "commands_run": ["bun test retry.test.js"],
  "tests_run": ["bun test"]
}
```

```bash
gx commit -m "retry: honor attempt limit" --context-file context.json
```

This is how a coding agent records *what it did* alongside *what changed*. Reviewers see the summary and the tests that ran next to the diff. MCP's `gx_commit` tool exposes these as first-class parameters, so agents rarely need to write the file themselves.

## gx status

```bash
gx status        # alias: gxs
```

Shows unstaged changes, local stacks (features), their revisions, and remote sync status.

```text
$ gx status

demo-repo  ● retry-backoff

› ● retry-backoff  s1 · feature/retry-backoff · main · draft · ↑2
        ↑ zlsrnuk  add jitter to backoff delays  latest
        ↑ qlmmuyy  add exponential backoff helper
```

Reading the stack header, left to right: stack name, `s1` short alias (usable in commands like `gx push s1`), the Git branch it exports to, the base branch, publish state (`draft` until pushed), and `↑2` — two revisions ahead of the remote.

| Flag | Meaning |
| --- | --- |
| `--json` | machine-readable stack summary |
| `--agent` | stable, line-oriented text for agents (see below) |
| `--all` | list all changed files in the git working tree sections |
| `-i`, `--interactive` | open the interactive status browser |

`--agent` is the format coding agents should parse when not using MCP — one `key=value` line per stack and revision:

```text
$ gx status --agent
next: "git add"
repo=demo-repo stacks=1 current=retry-backoff
stack name=retry-backoff alias=s1 ref=feature/retry-backoff base=main status=draft changes=2 published=0/2 sync=local current=true
revision id=qlmmuyyyupkm message="add exponential backoff helper" status=draft commit=14c101a1
revision id=zlsrnukorkyz message="add jitter to backoff delays" status=draft commit=ae0d5b62
```

### Subcommands

```bash
gx status list                     # all non-merged GX features (--json, --agent)
gx status edit <revision>          # reopen a recorded revision to keep working on it
gx status diff <revision-or-stack> # show the JJ diff for a revision or stack
```

```text
$ gx status diff zlsrnukorkyz
Added regular file jitter.js:
        1: export function jitter(ms) {
        2:   return ms / 2 + Math.random() * (ms / 2);
        3: }
```

## gx review

```bash
gx review                                 # alias: gxr
gx review "check auth rollback risks"
```

Reviews local changes using codebase context, captured sessions, review resources, and optional prompt guidance. Findings are printed as markdown and recorded to review history so future reviews can retrieve previous decisions.

AI reviewers are optional and resolve credentials in this order: your own key (`ANTHROPIC_API_KEY` / `OPENAI_API_KEY`, or `gx set key`), then GX Cloud when you are signed in (on your plan or free trial), then deterministic checks only — the review always completes, with a warning naming what was unavailable.

| Flag | Meaning |
| --- | --- |
| `[prompt]` | optional positional prompt to steer the review |
| `--scope <scope>` | focused review scope: `architecture`, `security`, `performance`, `onboarding`, `docs`, `dependencies`, `testing`, `maintainability` |
| `--focus <path>` | limit review to files under this path prefix |
| `--deep` | full-spectrum review with more local and indexed context |
| `--verbose` | include repo facts, docs, and changed files in the output |

Examples:

```bash
gx review --scope security                  # security-focused pass over the current changes
gx review --focus src/auth --deep           # deep review of just the auth directory
gx review "did we break the retry contract?"
```

## gx push

```bash
gx push              # push the current stack, like git push
gx push s1           # push a specific stack by name or alias
gx push --all        # push every accepted stack
```

Publishes stacks: normal Git branches and commits, linked sessions, and review metadata. Prints branch, GitHub push status, PR status/URL, and an Actions link when available. When an edited revision rewrites a stack, GX uses a guarded force-push with lease.

Like `git push`, the default is only the current stack — pushing everything requires the explicit `--all` so GX never publishes branches you did not ask to share.

With the pre-push hook from `gx init`, plain `git push` also triggers capture and cloud publish for the pushed refs.

## gx sync

```bash
gx sync              # sync the default remote
gx sync upstream     # sync a specific remote
```

Fetches remote Git and GX state before committing or pushing: updates remote bookmarks, catches up local state to merged/closed PRs, prunes stacks whose PRs reached a terminal state, and drains any queued cloud uploads.

Use it when GitHub moved (a branch was merged or closed), or when `gx push` reports remote divergence.

## gx auth

```bash
gx auth login                     # sign in through GitHub
gx auth login --name "work-mbp"   # set the machine name shown in the console
gx auth status                    # show current auth state (--json for scripts)
gx auth logout
```

Signs the CLI into GX Cloud through GitHub. Signed-in devices appear in the web app with machine name, GX version, last-used time, and session expiry.

## gx set key

```bash
gx set key                                            # interactive: pick provider, paste key
gx set key --provider anthropic --key "$ANTHROPIC_API_KEY"
```

Optional — GX works without a key, and signed-in users get AI features through GX Cloud. Set one when you want GX to call a specific provider or model directly. Stores the key in `~/.gx/inference.json` (or `$GX_HOME/inference.json`); an existing `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` in the environment is preferred when present. Providers: `anthropic`, `openai`.

## gx doctor

```bash
gx doctor          # diagnose capture, hooks, Codex routing, stale stacks
gx doctor --fix    # apply safe repairs
gx doctor --json   # machine-readable report
```

Checks local GX setup and workflow state: session capture health, Codex config routing, stacks whose base ref went missing, and stale stacks. `--fix` cleans up stale stacks, repairs missing base refs, and rewires configuration where it is safe to do so.

## gx report

```bash
gx report          # --json for the report id/URL
```

Uploads recent GX logs to support and prints a report ID and URL. Use it when something misbehaves and you want the team to see what happened. Needs GX Cloud: use a released install and `gx auth login`.

## Shortcuts

The CLI installer installs:

```bash
gxs   # gx status
gxr   # gx review
```

They are symlinks to the same `gx` binary.

## Bulk organize (advanced)

`gx generate` is hidden from `gx --help`. Use it when you want GX to organize a large working copy into smaller revisions automatically:

```bash
gx generate
gx status
gx push
```

| Flag | Meaning |
| --- | --- |
| `[filesets...]` | limit generation to these changed files or directories |
| `--exclude <path>` | exclude a changed file or directory; may be repeated |
| `--intent <text>` | intent prefix attached to generated revisions |
| `--json` | machine-readable plan and result |
| `--raw` | show full generate diagnostics in human output |

For most day-to-day work, prefer `git add` + `gx commit` — explicit scope beats bulk organization when you already know what belongs together.

## Surgery commands (advanced)

Hidden commands for explicit repair work, not the default flow:

```bash
gx edit            # pick a recorded revision to reopen and keep working on
gx edit <rev>      # reopen a specific revision
gx base            # show the GX authoring base and current ref
gx base --set main # return the authoring base to the default branch
```

```text
$ gx base
GX base
Base          main
Current       feature/retry-backoff
On base       no

Return        gx base --set main
```

## Diagnostics (advanced)

Hidden utility commands for capture and support:

```bash
gx capture sync         # force a session capture sync
gx ops diagnose doctor  # deeper ops diagnosis surface
```

Prefer the public `gx doctor` and `gx report` unless you need the deeper ops surface.
