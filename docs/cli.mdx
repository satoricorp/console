`gx` is the local CLI. It is open source and runs on your machine. It adds a quality and workflow layer around your existing repo instead of replacing GitHub.

You work in plain Git — `git add`, `git commit`, `git push` — and once `gx init` installs the hooks, GX records review context around your commits automatically: which session produced each change, and where it sits in your stack. GX adds a few commands of its own; it does not replace any Git command you already use.

## Core loop

Once `gx init` installs the hooks, you work entirely in plain Git. There is no GX save verb to learn — your normal commands do the GX work on the way through.

```bash
git add <files>                        # choose the scope of the change
git commit -m "describe this change"   # a hook records it as a GX revision
git status                             # inspect state with plain Git
git push                               # the pre-push hook captures sessions and publishes review context
```

A commit looks like any other — GX records the revision behind it without changing Git's output:

```text
$ git add src/retry.js
$ git commit -m "add retry helper with attempt limit"
[main b694d3be] add retry helper with attempt limit
 1 file changed, 12 insertions(+)
```

Behind that commit, GX's `prepare-commit-msg` and `post-commit` hooks record a GX **revision** — an editable review unit that carries context: which captured session produced it, and where it sits among your branches. On `git push`, the pre-push hook links each captured session to the hunks it changed and publishes the review bundle that becomes your PR summary.

A revision is a Git commit plus the review context GX records around it; a stack is just the Git branch those revisions sit on. You never leave Git to get them.

Provenance is inferred automatically. GX matches captured sessions to the commit's changed hunks, so the review bundle knows which session produced each change — there is no manual attach step, and agents do not declare provenance by hand.

GX adds a few commands on top of Git — and nothing that duplicates Git itself:

```bash
gx init      # set up hooks and identity in a repo (run once)
gx review    # AI review of your current change, with codebase + session context (alias: gxr)
gx doctor    # check capture, hooks, and workflow state
```

Setup and support commands round out the surface: `gx auth`, `gx set`, `gx version`, `gx report`, and `gx demo`.

## gx init

```bash
gx init
```

Prepares the current repository for GX: configures local identity, installs the Git hooks that record each commit as a revision and capture sessions on push (`prepare-commit-msg`, `post-commit`, and `pre-push`), installs Claude Code transcript-capture hooks, registers the MCP server with supported agent CLIs, and offers to add GX workflow instructions to `AGENTS.md`.

Run it once per repository.

| Flag | Meaning |
| --- | --- |
| `--name <name>` | user name to store in GX config (defaults to Git identity) |
| `--email <email>` | user email to store in GX config |
| `-y`, `--yes` | accept defaults and suppress prompts — use in scripts and agent sandboxes |

```text
$ gx init

Configured     gx identity as Ada Doc <ada@example.com>
Git hooks      ok: record on commit, capture on git push
Claude hooks   ok: Stop/SessionEnd transcript capture
Session        30 days retention
MCP            ok: claude
AGENTS.md      ok: added GX workflow instructions

Next           git add <files> && git commit -m "..."
```

## gx review

```bash
gx review                                 # alias: gxr
gx review "check auth rollback risks"
```

Reviews local changes using codebase context, captured sessions, review resources, and optional prompt guidance. Findings are printed as markdown and recorded to review history so future reviews can retrieve previous decisions.

AI reviewers are optional and resolve credentials in this order: your own key (`ANTHROPIC_API_KEY` / `OPENAI_API_KEY`, or `gx set key`), then GX Cloud when you are signed in (on your plan or free trial), then deterministic checks only — the review always completes, with a warning naming what was unavailable.

| Flag | Meaning |
| --- | --- |
| `[prompt]` | optional positional prompt to steer the review |
| `--scope <scope>` | focused review scope: `architecture`, `security`, `performance`, `onboarding`, `docs`, `dependencies`, `testing`, `maintainability` |
| `--focus <path>` | limit review to files under this path prefix |
| `--deep` | full-spectrum review with more local and indexed context |
| `--verbose` | include repo facts, docs, and changed files in the output |

Examples:

```bash
gx review --scope security                  # security-focused pass over the current changes
gx review --focus src/auth --deep           # deep review of just the auth directory
gx review "did we break the retry contract?"
```

## gx auth

```bash
gx auth login                     # sign in through GitHub
gx auth login --name "work-mbp"   # set the machine name shown in the console
gx auth status                    # show current auth state (--json for scripts)
gx auth logout
```

Signs the CLI into GX Cloud through GitHub. Signed-in devices appear in the web app with machine name, GX version, last-used time, and session expiry.

## gx set key

```bash
gx set key                                            # interactive: pick provider, paste key
gx set key --provider anthropic --key "$ANTHROPIC_API_KEY"
```

Optional — GX works without a key, and signed-in users get AI features through GX Cloud. Set one when you want GX to call a specific provider or model directly. Stores the key in `~/.gx/inference.json` (or `$GX_HOME/inference.json`); an existing `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` in the environment is preferred when present. Providers: `anthropic`, `openai`.

## gx doctor

```bash
gx doctor          # diagnose capture, hooks, Codex routing, stale stacks
gx doctor --fix    # apply safe repairs
gx doctor --json   # machine-readable report
```

Checks local GX setup and workflow state: session capture health, Codex config routing, stacks whose base ref went missing, and stale stacks. `--fix` cleans up stale stacks, repairs missing base refs, and rewires configuration where it is safe to do so.

## gx report

```bash
gx report          # --json for the report id/URL
```

Uploads recent GX logs to support and prints a report ID and URL. Use it when something misbehaves and you want the team to see what happened. Needs GX Cloud: use a released install and `gx auth login`.

## gx version

```bash
gx version
gx version --json   # machine-readable build metadata
```

## gx demo

```bash
gx demo
```

Interactive first-run walkthrough in a scratch session — safe to run anywhere; it does not touch your repository.

## Shortcuts

The CLI installer installs `gxr` as a shortcut for `gx review`:

```bash
gxr   # gx review
```

It is a symlink to the same `gx` binary.

## Diagnostics (advanced)

Hidden utility commands for capture and support:

```bash
gx capture sync         # force a session capture sync
gx ops diagnose doctor  # deeper ops diagnosis surface
```

Prefer the public `gx doctor` and `gx report` unless you need the deeper ops surface.
