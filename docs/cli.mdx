Initialize any repository with `gx init`. This installs git hooks that capture
your session context and pairs it with your code changes, giving gx
better context for review.

## gx CLI Overview

```bash
gx init         # set up hooks in a repo (run once)
gx review       # AI review of the current change (alias: gxr)
gx constraints  # pre-ship exit gate for the current change (alias: gxc)
gx auth         # sign in to gx Cloud
gx doctor       # diagnose capture, hooks, and publishing
gx version      # print the version
```

## gx init

```bash
gx init
```

`gx init` installs the Git hooks and registers the MCP server. Run it once per
repository.

| Flag | Meaning |
| --- | --- |
| `--name <name>` | user name to store in gx config (defaults to Git identity) |
| `--email <email>` | user email to store in gx config |
| `-y`, `--yes` | accept defaults and suppress prompts — use in scripts and agent sandboxes |
| `--global` | install the hooks machine-wide instead of for one repository |

### Global hooks

```bash
gx init --global
```

Installs the hooks once for every repository. The scripts chain to each
repository's own hooks of the same name, so husky, lefthook, and hand-written
hooks keep working. If a global hooks path is already set to something else,
`gx init --global` stops rather than overwriting it.

Opt a single repository out, from inside it:

```bash
git config gx.enabled false
```

Undo the machine-wide install:

```bash
git config --global --unset core.hooksPath
```

## gx review

```bash
gx review                                 # alias: gxr
gx review "check the auth rollback path"
gx review --scope security                # focused pass
gx review --focus src/auth --deep         # deep review of one directory
```

Reviews the current codebase state. `gx review` uses your indexed codebases,
two separate models to identify the most important issues with a judge to
dedupe findings. This can be run in the terminal or via [MCP](/docs/mcp).

| Flag | Meaning |
| --- | --- |
| `[prompt]` | optional positional prompt to steer the review |
| `--base <ref>` | review the commit range `<ref>...HEAD` instead of the working tree |
| `--scope <name>` | focused lens: `architecture`, `security`, `performance`, `onboarding`, `docs`, `dependencies`, `testing`, `maintainability` |
| `--focus <path>` | limit the review to files under a path prefix |
| `--repo` | review the whole repository rather than the current change |
| `--deep` | full-spectrum review with more local and indexed context |
| `--verbose` | include repo facts, docs, and changed files |
| `--json` | print the report as JSON |
| `--fail-on <level>` | exit non-zero when findings at or above this level survive |
| `--no-publish` | skip posting the PR review comment and recording review history |

### What gets reviewed

1. `--base <ref>` when given — the range `<ref>...HEAD`
2. Otherwise a dirty working tree
3. Otherwise the branch's commits against an auto-detected base (`main`,
   `master`, `origin/main`, `origin/master`), or the last commit when HEAD is
   the base branch

If nothing was found, `gx review` says so. "Nothing was reviewed" is its own
outcome and never counts as a clean pass.

### Read-only

`gx review` does not mutate any logic, and doesn't require `gx init`
(`gx init` is required for PR summaries and chat).

### As a CI gate

```bash
gx review --base origin/main --fail-on strong --no-publish
```

`--fail-on` fails the review when findings at or above the level survive:

| Level | Meaning |
| --- | --- |
| `none` | never fail (default) |
| `any` | fail on anything the review raised |
| `speculative` | findings at `speculative` strength or above |
| `worth-exploring` | findings at `worth-exploring` strength or above |
| `strong` | findings at `strong` strength or above |
| `blocking` | only findings that should stop a merge |

Exit codes:

| Code | Meaning |
| --- | --- |
| `0` | reviewed, and nothing at or above the threshold survived |
| `3` | findings at or above the threshold survived |
| `4` | nothing was reviewed — a gate should not pass without inspecting code |

Pair with `--no-publish` so CI never posts PR comments, and `--json` to parse
findings yourself.

## gx constraints

```bash
gx constraints                       # alias: gxc
gx constraints "fix auth timeout"    # state the intent for the back-pressure gate
gx constraints --verbose             # list the source files behind each gate
gx constraints --md                  # markdown report (what agents relay)
```

The pre-ship exit gate. Checks the current change against six constraints and
reports PASS, FAIL, or SKIPPED for each, plus a ship / no-ship verdict — run
it before opening a PR. Deterministic checks decide what they can; one AI
judgment call covers the rest, grounded in the same indexed context
`gx review` uses.

| Gate | What it checks |
| --- | --- |
| Correctness | the project's own tests and builds: `go test`, `tsc`, `cargo check`, `dotnet build`, `flutter analyze`, `pytest` |
| Security | secrets in added lines; dependency audits (`govulncheck`, `npm audit`, `pip-audit`, `cargo audit`) |
| Code health | linters, reviewability (large changes warn, they don't block), and whether tests accompany the sources |
| Back-pressure | is every part of the change in service of the stated intent — scope creep, regenerated bloat, unjustified new dependencies |
| Accessibility | added UI elements stay usable by keyboard and screen reader; auto-skips when no UI files changed |
| Performance | hot-path regressions on perf-relevant changes; the model must justify a pass explicitly |

| Flag | Meaning |
| --- | --- |
| `[intent]` | optional positional statement of what the change is meant to do |
| `--base <ref>` | check the commit range `<ref>...HEAD` instead of the working tree |
| `--verbose` | list the source files behind each gate |
| `--md` | print the report as markdown |
| `--json` | print the full report as JSON |
| `--skip-gates <list>` | comma-separated gates to skip |
| `--timeout <dur>` | whole-run budget (default 5m) |
| `--report-only` | always exit 0; read the verdict from the report |

Findings about the change show its diff hunk — colored in the terminal, a raw
`diff`-fenced block in markdown — while findings about untouched lines show
the current source, syntax-highlighted. Every report ends with a **How to
resolve** section: one numbered step per finding with the code and the fix.
A missing tool is never a failure — an auditor that isn't installed or can't
reach its database is reported as skipped evidence.

### As a CI gate

The exit code is the gate by default — no opt-in flag needed:

| Code | Meaning |
| --- | --- |
| `0` | ship — every gate passed or was legitimately skipped |
| `3` | no-ship — at least one gate failed |
| `4` | nothing to check — a gate should not pass without inspecting code |
| `5` | degraded — the AI gates could not run, so a pass would be unearned |

Use `--report-only` to opt out of the coded exits and read the verdict from
the report instead.

## gx auth

```bash
gx auth login
gx auth status
gx auth logout
```

Signs the CLI into gx Cloud through GitHub.

## gx doctor

```bash
gx doctor            # diagnose capture, hooks, auth, and the publish queue
gx doctor --fix      # apply safe repairs
gx doctor --json     # machine-readable report
gx doctor --report   # send this diagnosis and recent logs to support
```

## gx version

```bash
gx version
gx version --json
```

## Shortcuts

The installer links `gxr` and `gxc` to the same binary:

```bash
gxr   # gx review
gxc   # gx constraints
```
