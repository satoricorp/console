Start with GX when you want coding agents to produce reviewable work instead of one large undifferentiated diff.

The usual path is:

1. Install the CLI.
2. Sign in with GitHub.
3. Initialize GX in a repository.
4. Stage and commit with Git, review, and push.

## Install

The CLI runs on macOS and Linux (arm64 / amd64):

```bash
curl -fsSL https://download.gx.run/install.sh | sh
```

On Windows, run GX inside WSL. You can request a native Windows build from the [download page](/download).

The installer places three binaries in `~/.local/bin`:

| Binary | Purpose |
| --- | --- |
| `gx` | the CLI |
| `gx-mcp` | stdio MCP server for coding agents ([MCP setup](/docs/mcp)) |
| `gxr` | shortcut for `gx review` |

Verify the install:

```bash
gx version   # prints the installed version
gx doctor    # checks capture, hooks, and workflow state
```

## Sign in

GX uses GitHub for identity. Cloud sign-in is required to push metadata and use GX code review.

```bash
gx auth login
gx auth status
```

The web app sign-in and CLI sign-in are linked through your GitHub account. After signing in from the CLI, you can see signed-in CLI devices in the web app, including machine name, GX version, last-used time, and session expiry. Pass `--name` to control how the machine appears there:

```bash
gx auth login --name "work-laptop"
```

Log out with:

```bash
gx auth logout
```

## Initialize a repo

Run `gx init` once, from the repository you want GX to manage:

```text
$ gx init

Configured     gx identity as Ada Doc <ada@example.com>
Git hooks      ok: record on commit, capture on git push
Claude hooks   ok: Stop/SessionEnd transcript capture
MCP            ok: claude
AGENTS.md      ok: added GX workflow instructions

Next           git add <files> && git commit -m "..."
```

Line by line:

- **gx identity** — the name and email recorded on GX revisions. Defaults to your Git identity; override with `gx init --name "..." --email "..."`.
- **Git hooks** — `prepare-commit-msg` and `post-commit` record each `git commit` as a GX revision, and a `pre-push` hook captures sessions and publishes GX metadata when you `git push`.
- **Claude hooks** — Claude Code `Stop`/`SessionEnd` hooks, so agent transcripts are captured as GX sessions.
- **MCP** — registers the [GX MCP server](/docs/mcp) with supported agent CLIs found on the machine.
- **AGENTS.md** — offers to append GX workflow instructions telling agents working in this repo to use plain Git (GX's hooks record the revision).

For scripts and agent sandboxes, `gx init -y` accepts all defaults and suppresses interactive prompts.

To skip the per-repository step entirely, `gx init --global` installs the hooks once for every repository on the machine — useful when you don't want to remember `gx init` in a new clone. See [CLI → Machine-wide hooks](/docs/cli#machine-wide-hooks).

## Optional: bring your own model key

You do not need a model API key to use GX. The core workflow is fully deterministic, and once you sign in, AI features like `gx review` run through GX Cloud on your plan or free trial.

Set your own key only when you want GX to call a specific provider or model directly:

```bash
gx set key                                              # interactive: pick provider, paste key
gx set key --provider anthropic --key "$ANTHROPIC_API_KEY"   # scripts
```

GX looks for an existing `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` in the environment first, and stores a pasted key in `~/.gx/inference.json` (or `$GX_HOME/inference.json`). When both are available, your own key takes precedence over GX Cloud.

Paid pull request features (PR Summaries, `@gx` chat) always run through GX Cloud, never your local keys.

## First revision

After making changes, stage the files that belong together and commit them with plain Git:

```text
$ git add src/retry.js
$ git commit -m "add retry helper with attempt limit"
[main b694d3be] add retry helper with attempt limit
 1 file changed, 12 insertions(+)
```

What happened:

- `git add` chose the scope — only `src/retry.js` is part of this revision. Use `git add -p` to select individual hunks.
- `git commit` landed the change on the current branch as usual. Behind it, GX's `prepare-commit-msg` and `post-commit` hooks recorded a GX revision (`qltmnmynnyzk`) that carries the review context around the commit.
- Because no coding session was captured for this commit, the revision's provenance is `absent`. When an agent session is captured, GX matches it automatically and links it instead.

Then publish:

```bash
git status   # inspect first
git push     # the GX pre-push hook captures sessions and publishes metadata
```

`git push` pushes normal Git refs; with the GX hook installed, capture and cloud publish happen on the way out.

## Build a stack

A stack is just an ordinary Git branch with more than one commit on it. Start a branch for a line of work, then keep committing to grow it:

```text
$ git checkout -b feature/retry-backoff
Switched to a new branch 'feature/retry-backoff'

$ git add src/backoff.js
$ git commit -m "add exponential backoff helper"
[feature/retry-backoff 14c101a1] add exponential backoff helper
 1 file changed, 18 insertions(+)

$ git add src/jitter.js
$ git commit -m "add jitter to backoff delays"
[feature/retry-backoff ae0d5b62] add jitter to backoff delays
 1 file changed, 6 insertions(+)
```

GX recorded a revision for each commit as it landed. Inspect the stack with plain Git — it is just the branch's own commits, newest first:

```text
$ git log --oneline main..feature/retry-backoff
ae0d5b62 add jitter to backoff delays
14c101a1 add exponential backoff helper
```

The branch `feature/retry-backoff` is the stack: `main` is its base, and each commit on it is a GX revision. When you `git push`, the pre-push hook publishes the whole branch as a reviewable stack.

## Agent workflow

Agents work in plain Git, exactly like you do:

1. Stage with `git add`
2. Commit with `git commit` — GX's hooks record the revision
3. Push with `git push` — the pre-push hook captures sessions and publishes metadata

The MCP server adds one tool worth wiring up: agents can run `gx_review` for review context on the current change.

See [MCP setup](/docs/mcp) for `add-mcp`, Executor, and per-tool parameters.
