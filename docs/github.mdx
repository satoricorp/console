GX adds paid review features inside GitHub pull requests.

The CLI can record and publish stacks locally for free. GitHub PR Summaries and `@gx` chat run through GX Cloud and require the paid PR feature set (or an active free trial).

## Prerequisites

1. Sign in with `gx auth login` (or sign in on the console).
2. Install the GX GitHub App on your personal account or organization so GX can post comments and read PR context. From the console, use **Install on GitHub** after the download step (`/install-github`), or open [github.com/apps/gx-faster-code-review](https://github.com/apps/gx-faster-code-review) directly.
3. Point the GitHub App webhook at the GX Cloud API:

```text
https://api.gx.run/github/webhook
```

4. Publish work through GX (`git push` with the GX pre-push hook). A PR created only in the GitHub UI will not get a GX summary until that branch is pushed through GX with capture metadata present.

## PR Summaries

GX writes one rich PR Summary into the **pull request description** (not a separate comment). Any human description already on the PR stays above the GX block; later regenerations replace only the GX section.

When opening a PR (`gh pr create` or the GitHub UI), leave the body for your own notes — do **not** seed a `## Summary` section. GX Cloud appends the rich summary once the PR exists and publish metadata is available.

The summary is intentionally short. It should tell reviewers:

- what changed
- why it changed
- which files deserve attention first
- which files are mechanical or safe to skim
- what session or agent context is relevant

The goal is to point reviewers to the important parts of the change instead of forcing them to read every line with no context.

### When summaries are generated

GX posts summaries from these paths:

- **GitHub webhook** — on `pull_request` `opened` / `synchronize`, when the branch already has a published GX event
- **After publish** — when plain `git push` (with the GX pre-push hook) has a PR number and the GitHub App is installed

The [`POST /v1/summaries/generate`](/docs/reference/api) API stores a summary in GX Cloud. It does **not** write the PR description by itself.

### Trial and paid access

Orgs on the free plan get PR Summaries during a free trial window (default 7 days from org creation, or the entitlement returned by GX Cloud). After the trial ends, summaries require a paid plan. When quota blocks a summary, GX can post an upgrade comment on the PR instead.

## Chat with `@gx`

Mention `@gx` in a PR comment to ask questions about the pull request.

Ask for orientation:

```text
@gx summarize this PR for someone reviewing it cold
@gx which files should I review first?
@gx what is safe to skim?
```

Ask about a specific part of the diff:

```text
@gx explain the auth callback changes
@gx why did the migration file change?
@gx what does this new background job do?
```

Ask for risk or follow-up review:

```text
@gx what is the highest-risk change in this PR?
@gx are there missing tests?
@gx is this related to the previous retry bug?
```

GX answers from available review sources and cites the sources it used. Because published revisions carry session provenance, `@gx` can answer "why" questions — what the author asked for, which commands and tests ran — that a plain diff cannot.

### Override learned rules

You can use `@gx` to retire a learned rule:

```text
@gx skip rule never use var
@gx do not enforce this migration naming rule
```

When a matching active rule exists, GX retires it and records the override. Rule overrides require GitHub **write**, **maintain**, or **admin** permission on the repository. Collaborators without write access are denied.

## Data sources

GX answers from the current PR first: the published GX revision diffs, changed hunks, file paths, PR comments, and the latest PR Summary.

When available, GX can also use captured coding-session context, indexed codebase context, previous findings, learned rules, and git blame history. Current PR changes remain the source of truth for what changed.

## GitHub App

Install from the console (**Install on GitHub**) or at [github.com/apps/gx-faster-code-review](https://github.com/apps/gx-faster-code-review). To post summaries and replies, GX needs installation-scoped access for the repository. The local CLI can still record and push branches without the paid PR feature set. The paid features are the GitHub-hosted review layer: PR Summaries, `@gx` chat, and cloud-backed review context.
