---
title: "CLI"
description: "Use the open-source gx CLI to generate stacks and revisions, inspect status, review changes, and publish normal Git output."
---

`gx` is the local CLI. It is open source and runs on your machine. It adds a quality and workflow layer around your existing repo instead of replacing GitHub.

GX still produces ordinary Git branches and commits as output. The difference is that GX models the work first as reviewable revisions inside ordered stacks, with captured session context attached.

## gx init

```bash
gx init
```

Prepares the current repository for GX. It configures local identity, initializes GX workflow state, and sets up capture support for coding-session provenance.

Run it once per repository:

```bash
gx init
```

## gx generate

```bash
gx generate
```

Turns current working-copy changes into reviewable stacks and revisions. This is the main command agents should use after making code changes.

`gx generate` is built for messy work: it inspects changed hunks, structural signals, dependencies, and session context, then saves the work in an order that is easier to review.

You can also generate only part of the current diff:

```bash
gx generate src/auth.ts --exclude "**/*.test.ts"
```

## gx status

```bash
gx status
```

Shows the current GX state: unstaged changes, local stacks, revisions, and remote sync status.

Use this after `gx generate` to inspect what GX created before pushing.

Machine-readable output:

```bash
gx status --json
```

## gx push

```bash
gx push
```

Publishes generated stacks. GX pushes normal Git branches and commits, uploads linked sessions and review metadata, and prints GitHub/Review URLs when available.

Run this when the generated revisions look ready to share.

## gx sync

```bash
gx sync
```

Fetches remote Git and GX state before generating or pushing. Use it when GitHub moved, a branch was merged, or `gx push` reports remote divergence.

Recommended agent flow starts with sync:

```bash
gx sync
gx generate
gx status
gx push
```

## gx review

```bash
gx review
```

Reviews local changes using codebase context, captured sessions, review resources, and optional prompt guidance.

You can ask for a focused review:

```bash
gx review "check auth rollback risks"
```

## gx add

```bash
gx add -m "describe this revision"
```

Records the current work as a specific revision with the message you provide. Use this when you already know the exact revision boundary.

For most agent workflows, prefer `gx generate`; it can infer stacks and revision boundaries for messy changes.

## gx edit

```bash
gx edit <revision>
```

Re-enters an existing revision so you can continue working on it. With no revision argument, GX can show a picker of recent mutable changes.

Use this for targeted repair after a generated revision needs follow-up.

## gx doctor

```bash
gx doctor
```

Checks local GX setup and workflow state. Use it when capture, auth, or repository setup looks wrong.

Some safe repairs can be run with:

```bash
gx doctor --fix
```

## gx auth

```bash
gx auth login
gx auth status
```

Signs the CLI into GX through GitHub and shows the current auth state. Web app sign-in and CLI sign-in are linked by your GitHub account.

## gx version

```bash
gx version
```

Prints the installed GX version.

Machine-readable output:

```bash
gx version --json
```

## Shortcuts

The CLI installer also installs three shortcuts:

```bash
gxg # gx generate
gxs # gx status
gxr # gx review
```

They are symlinks to the same `gx` binary. When the binary starts as `gxg`, `gxs`, or `gxr`, it dispatches to the matching command.

## Advanced commands

GX also includes advanced commands for diagnostics, capture, and support.

Use these when needed:

```bash
gx report
gx capture sync
gx ops
```

- `gx report` sends logs to support.
- `gx capture sync` uploads pending captured session data.
- `gx ops` groups advanced capture, diagnostics, and ingest commands.

## Model credentials

The open-source CLI can use provider credentials for local stack and revision inference:

```bash
export OPENAI_API_KEY="..."
export ANTHROPIC_API_KEY="..."
```

Use these when you want local CLI/MCP inference to use your own OpenAI or Anthropic credentials. Paid pull request features run through GX Cloud.
