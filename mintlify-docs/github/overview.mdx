GX adds paid review features inside GitHub pull requests.

The CLI can generate and publish stacks locally. GitHub PR Summaries and `@gx` chat run through GX Cloud and require the paid PR feature set.

## PR Summaries

GX can post a PR Summary comment on a GitHub pull request after a stack is published.

The summary is intentionally short. It should tell reviewers:

- what changed
- why it changed
- which files deserve attention first
- which files are mechanical or safe to skim
- what session or agent context is relevant

The goal is to point reviewers to the important parts of the change instead of forcing them to read every line with no context.

## Chat with `@gx`

Mention `@gx` in a PR comment to ask questions about the pull request.

Ask for orientation:

```text
@gx summarize this PR for someone reviewing it cold
@gx which files should I review first?
@gx what is safe to skim?
```

Ask about a specific part of the diff:

```text
@gx explain the auth callback changes
@gx why did the migration file change?
@gx what does this new background job do?
```

Ask for risk or follow-up review:

```text
@gx what is the highest-risk change in this PR?
@gx are there missing tests?
@gx is this related to the previous retry bug?
```

GX answers from available review sources and cites the sources it used.

You can also use `@gx` to override learned rules:

```text
@gx skip rule never use var
@gx do not enforce this migration naming rule
```

When a matching active rule exists, GX retires it and records the override.

## Data sources

GX answers from the current PR first: the published GX revision diffs, changed hunks, file paths, PR comments, and the latest PR Summary.

When available, GX can also use captured coding-session context, indexed codebase context, previous findings, learned rules, and git blame history. Current PR changes remain the source of truth for what changed.

## GitHub App

To post summaries and replies, GX needs GitHub access for the repository. The GitHub App provides installation-scoped access for posting comments and reading PR context.

The local CLI can still generate and push branches without the paid PR feature set. The paid features are the GitHub-hosted review layer: PR Summaries, `@gx` chat, and cloud-backed review context.
